# UI redesign — decisions taken during execution

Recorded 2026-08-30. During the ten-task execution of
`docs/superpowers/plans/2026-08-30-health-console-ui-redesign.md`, a number of
conflicts, plan defects and review findings had to be settled without stopping
the run. Each is listed here with what was decided and what it costs if the
decision was wrong, so it can be reviewed and reversed.

- Ruling R1: Execute on the existing `feat/foundation` branch rather than a new worktree — the spec (836d727) and plan (8f0a666) are already committed there, and splitting them from their implementation would scatter one change across two branches. Cost if wrong: the branch carries both the foundation work and the redesign, making a later bisect coarser.
- Ruling R2: Task 4 Step 2 predicts `import ../i18n.js` throws because the module touches `localStorage`/`document` at module scope. It does not — every such access in today's `app.js` already sits inside a function body, so Step 3 is likely a no-op and the unit test may pass on first run. The deliverable of Task 4 is the harness, not a red-green cycle, so a first-run pass is acceptable and must be reported rather than manufactured into a failure. The implementer must still verify by reading the module that no top-level statement references `document`, `localStorage`, `location` or `navigator`, and fix it if one does. Cost if wrong: a test that never demonstrated it can fail.
- Ruling R3: Task 9 Step 4's `app.js` calls `clearCache()` on the refresh button but its import line imports only from `./expert.js`. Add `import { clearCache } from "./history.js";`. Cost if wrong: none — without it the module throws on load, which is immediately visible.
- Ruling R4: Spec §6 requires the thermal chart card to draw `cpu.temp.pkg` **and** the discovered `thermal.*` zones; the plan's `CHART_CARDS` lists only `cpu.temp.pkg`. The spec is the binding authority, so Task 9 must build the thermal card's series list at render time from the zone keys present in `state.probes.thermal.zones`, each labelled with its raw zone name (spec §9 already classes zone names as untranslated diagnostic material). Cost if wrong: a busier thermal chart than intended, or — if the zone list is empty on this machine — a card that looks identical to the plan's version.
- Ruling R5: Task 5's Produces block omits `whenThemeChanges`, which Task 9 relies on. It is added to Task 5's interface contract so the Task 5 reviewer gates it. Cost if wrong: none — Task 9 would fail loudly.
- Ruling R6: Task 3 brief lists markStreamDown() in its Interfaces block, but the concrete Step 5/7 code never uses it -- connect() sets isStale internally on the SSE error event. The implementer followed the concrete steps and omitted it. Accepted: the Interfaces block was my error, an unused export would be dead code, and the review rubric treats dead code as a defect. Cost if wrong: none identified; no caller exists.
- Ruling R7: simple.js imports hasMeasurement from stream.js, which the brief prose did not list. Accepted: the alternative is duplicating the "what counts as a measurement" rule in two modules, which is exactly the kind of divergence that lets a page show a score for EMPTY_STATE. Import graph verified acyclic: dom <- i18n <- stream <- simple <- app. Cost if wrong: none; the dependency is one-way.
- Ruling R8: Step 10 (browser check) was not performed -- no browser tool was available to the implementer. It fell back to node --check on every module plus curl of the page and each module over HTTP (all 200, correct content-type, old /static/app.js now 404). That proves the modules parse and are served, NOT that they wire together at runtime. Carried to the final manual verification checklist (Task 10) as a must-do, and flagged to the reviewer to verify the import graph and export/import agreement statically. Cost if wrong: a runtime module error that ships unnoticed until the page is opened.
- Ruling R9: The Important finding (render() no longer records lastState nor calls markFreshness, so the freshness banner reads "no measurement yet" under a card showing a real score whenever the SSE stream is down but /api/now worked) is CONFIRMED and originates in my brief Step 7 verbatim code, not implementer freelancing. The plan text mandated it; the spec overrides. Spec section 11 requires the page to state honestly since when data froze, and the surrounding comments the refactor preserved exist to enforce exactly that. Fixing per the reviewer patch: stream.js gains noteState(), app.js render() calls noteState + markFreshness(isMeasurementStale(state)). Cost if wrong: none identified -- it restores pre-refactor semantics exactly.
- Ruling R10: Minor "globalThis.healthConsole lost translate and formatBytes" is folded INTO fix round 1 rather than deferred. It is a one-line change in a file already being edited, and the task overriding requirement is behaviour preservation -- a debug surface that silently shrinks is still a behaviour change. Cost if wrong: one extra line in the fix diff.
- Ruling R11: Plan gap spanning Tasks 5 and 8. Task 5 style.css keeps only ".finding { border-left-width: 4px !important }" and relies on Bootstrap .card for the background, border-style and colour base -- but simple.js card() emits className "finding severity-X" with no Bootstrap classes, and no task adds them. border-left-width with the default border-style: none renders NOTHING, so finding cards currently have no visual severity indicator at all and no card chrome. Assigned to Task 8, which owns simple.js rendering: card() must emit "finding card severity-X" with the body wrapped in a div.card-body, matching the approved mockup. NOT assigned to Task 5, whose file list excludes simple.js. Accessibility is not breached in the interim -- severity still travels as icon plus word in the badge, so colour was never carrying it alone. Cost if wrong: three tasks of visually bare findings on an unshipped branch.
- Ruling R12: Important -- accordion triggers carry data-bs-toggle but no aria-expanded/aria-controls. Reviewer traced the vendored bootstrap bundle: _addAriaAndCollapsedClass runs only from the Collapse constructor, and the accordion data-api creates that instance lazily on FIRST CLICK, so on page load a screen reader hears "Raw data, button" with no disclosure semantics at all. Real defect against spec section 10.2, enters the fix loop.
- Ruling R13: Minor "matchMedia listener fires on every OS flip even when the stored choice is explicit" is folded INTO the fix round rather than deferred, because Task 9 registers chart redraws on whenThemeChanges -- an unguarded listener would redraw every chart on an OS flip the page deliberately ignores. One-line guard. Cost if wrong: a redundant redraw.
- Ruling R14: Minor "flash of wrong theme on load" is also folded in. data-bs-theme is a static light attribute and the real theme is applied by a deferred type=module script, so a returning dark-theme reader gets a white flash on every load -- a genuine regression versus the old prefers-color-scheme CSS, which the browser honoured before any script ran. CSP blocks an inline head script, but a small SYNCHRONOUS non-module script from /static/ is allowed by default-src self. Fixing rather than deferring: this console is opened at night on a laptop, and the fix is about eight lines. Cost if wrong: one extra small file in web/js/.
- Ruling R15: Critical -- fetchSeries does "body.points || []" and "body.depth_days ?? 0" after checking only response.ok, so a 200 with a missing or null points field resolves as a normal empty Series AND is cached, making a fabricated "nothing recorded" permanent for the page lifetime. Cannot fire against todays paired server (it always sends the three fields) but nothing in the module enforces that pairing, and the module exists precisely to keep "we could not ask" apart from "nothing was recorded". Fixing: validate the shape and throw HistoryError. Cost if wrong: none identified.
- Ruling R16: Important -- response.json() sits outside the try/catch, so a 200 with a corrupt or truncated body rejects with a native SyntaxError rather than a HistoryError. Not cached, so no false data, but it breaks the error taxonomy every caller will be written against. Fixing.
- Ruling R17: Important -- the cache-key ambiguity unit test proves nothing. Reviewer verified the chosen case passes even with the separator deleted entirely, and found a real collision under the shipped scheme: cacheKey("a","b c") and cacheKey("a b","c") both yield "a b c". Latent today because metric ids are dot-separated tokens and ranges come from a fixed enum, but the invariant is unenforced and the test papers over it. Fixing by making the key unambiguous by construction (JSON.stringify of the pair) and rewriting the test to actually demonstrate the property.
- Ruling R18: Important -- "normalized: true" sits at chart options level, but Chart.js reads it as a DATASET property. Reviewer grepped the vendored bundle: the string appears only inside private TimeScale._normalized machinery, no code path reads options.normalized. Dead configuration that contradicts its own comment. Fixing by moving it onto the dataset objects. Cost if wrong: an ignored property either way, so none.
- Ruling R19: Important -- summarise() returns the last FINITE sample as "current", but ui.chart.summary renders it as "currently {current}". With a trailing null bucket (collector hiccup, freshest bucket unpopulated) the accessible description asserts a live reading from stale data. Same class of dishonesty as the empty-series invariant, one gap down. Chose to keep last-known-valid semantics and correct the WORDING in both catalogues rather than change the data, because a chart summary that simply omits a value when the last bucket is empty is less useful than one that says when the value is from. Adding a comment stating the semantics and a unit test locking them. Cost if wrong: wording slightly more verbose.
- Ruling R20: folding the two deferred Minors (no unit test for summarise all-null branch, none for metricLabel fallback) into this fix round. The reviewer explicitly said the metricLabel one must not be deferred past Tasks 8/9, where it becomes user-visible, and both are one-line additions to a test file already being edited.
- Ruling R21: folding the Task 2 deferred minor (fr.json "librairie" -> "bibliotheque") into this same round. It is shipped French product text in a file this round already touches, and carrying it to the final wave risks losing it for no benefit. Cost if wrong: one unrelated line in the fix diff, clearly labelled.
- Ruling R22: PLAN DEFECT found by me before dispatching Task 8. renderSimple() runs on every SSE event -- every 2 seconds. The plan has it call attachSparkline() per finding and redraw the verdict gauge each time, while host.textContent = "" detaches the old canvases. Two consequences the plan never addresses: (a) every repaint constructs new Chart instances that are never destroyed and stay registered in charts.js live Set -- roughly 30 leaked charts per minute per finding; (b) each new chart replays its entry animation, so Simple mode would visibly pulse every 2 seconds for any reader who has not asked for reduced motion. Ruling: Task 8 must destroy charts before detaching their canvases, and must skip the findings repaint entirely when the findings signature has not changed. Cost if wrong: without it the page leaks memory and flickers -- both would have shipped, since no test in this repository observes either.
- Ruling R23: implementer concern 1 -- the verdict gauge is destroyed and redrawn every tick even when the score is unchanged, so it replays its entry animation every 2 s. This is correctness, not a scoped decision: my correction (A) named the findings rebuild explicitly and failed to say the gauge is the same problem. Sent back as a pre-review fix rather than carried into the review loop, per the DONE_WITH_CONCERNS handling rule. Cost if wrong: a pulsing health score on the view aimed at non-technical readers.
- Ruling R24: PLAN DEFECT found by me before dispatching Task 9. redrawCharts() clears the chart grid then appends cards one at a time with awaits in between. Two rapid clicks on the range buttons run two invocations concurrently, both appending into the same grid -- the reader gets duplicated or interleaved cards from two different windows, with no error. Ruling: Task 9 must guard with a generation counter, where a redraw that is no longer the newest abandons its work instead of appending. Cost if wrong: a garbled Expert grid that only a fast clicker sees, which is exactly the kind of defect that survives to production.
- Ruling R25: PLAN DEFECT -- both simple.js and the planned expert.js write the raw JSON into #raw, which now lives inside the Expert accordion. Two owners for one element. Ruling: expert.js owns it; the two writes in simple.js are removed. renderExpert only runs when Expert mode is visible, which is the only time that element is observable, so nothing is lost. Cost if wrong: the raw JSON pane goes stale while Expert mode is hidden -- unobservable by construction.
- Ruling R26: Important 1 -- depth line takes Math.min over ALL series including the ones just filtered out as empty, and available_depth_seconds returns 0 for a metric with no rows. A Temperature card drawing 30 days of cpu.temp.pkg alongside a zone that has not yet rolled into metric_5m prints "Only 0 days of history so far". Exactly the false statement the depth line exists to prevent. Fix: minimum over drawable.
- Ruling R27: Important 2 -- describeSeries pairs metrics[0] LABEL with drawable[0] DATA, which diverge as soon as the first series is empty. On a machine whose hwmon names miss PACKAGE_HINTS (ARM boards, acpitz-only laptops) there is no cpu.temp.pkg series, so the screen-reader label announces "Processor temperature" over another zone numbers. A canvas has no other accessible content, so this is all an AT user gets. Fix: keep metric and series paired.
- Ruling R28: Important 3 -- cpu.usage and load.1 both draw in --hc-info, and every thermal zone draws in --hc-info. The legend maps distinct labels to one identical swatch, so colour distinguishes nothing in the only place it is the sole channel. Fix: index a palette per dataset.
- Ruling R29: Important 4 -- a locale change repaints chrome, range buttons, tiles and the probe table but never redraws the charts, whose titles, legends, depth sentences and aria-labels are all produced at draw time. Switching to French in Expert mode leaves a half-French page. One line.
- Ruling R30: Important 5 -- the depth epsilon 0.05 exceeds the entire 1h window (0.0417), making ui.chart.depth_short unreachable on that range; and maximumFractionDigits 1 renders a 20-minute-old console as "History available: 0 days" under a chart visibly holding points. - Ruling R31: Important 6 -- switchMode now runs before the initial /api/now render, so a reader whose stored mode is Expert triggers redrawCharts with lastKnownState() null and silently loses every thermal zone on load, indistinguishable from a machine that genuinely has none. Fix: move switchMode below the initial render, which also completes the ordering fix the implementer was reaching for.
- Ruling R32: folding in Minor 1 (generation-counter test asserts only that the word "generation" appears, so deleting all three guard comparisons leaves it green) and Minor 3 (regex blind-spot comment). Both cheap, and Minor 1 currently guards a race with nothing.
- Ruling R33: folding in the thead half of Minor 2. Adding three catalogue keys is contained. NOT folding in the raw English status values (ok/unavailable/incoherent): those are diagnostic material, consistent with the existing raw-detail precedent where a probe untranslated reason is shown behind a translated lead-in. - Ruling R34: implementer added TWO depth keys (ui.chart.depth_hours and ui.chart.depth_short_hours) where I described one. Accepted, and it is the better reading: tightening the epsilon makes the short branch newly reachable on the 1h range with sub-day depths, so a single hours key would have reintroduced the identical "0 days" falsehood in the short branch. ## Corrections found by the first human to see the page rendered

Nothing on this branch was ever seen in a browser during development — no browser
tool was available. The first two defects a person found in two looks:

- **The verdict gauge rendered 700 px tall.** `responsive: true` makes Chart.js
  size a canvas from its parent, and the inline height it writes beats a
  stylesheet's `height: auto`. Fixed with a bounded `.gauge-holder`, matching the
  `.chart-holder` pattern already in the stylesheet.
- **Bootstrap's `data:image/svg+xml` icons were blocked by the CSP.** §4.2 of the
  redesign spec is titled "No CSP relaxation" and reached that conclusion by
  checking inline *styles*; it never considered inline *images*. The accordion
  chevron and the select arrow did not render. Fixed by widening the policy to
  `default-src 'self'; img-src 'self' data:` — images only, no script source
  widened, no external origin added.

A third console error, an inline script blocked under `script-src-elem`, came from
a browser extension and is the policy working as intended. No change made.
